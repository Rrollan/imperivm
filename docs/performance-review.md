# Производительность нового представления — 05.10.2026

Проверена production-сборка Next 14.2.35 во встроенном браузере Codex на Apple M1, WebGL2 / ANGLE Metal. Метрики выводит собственный скрытый DOM `output[data-perf]` только при `?debug=1`. CPU-таймер включает обновление анимаций и вызов scene.render; это не GPU timer. Сэмплы сбрасываются при действии, первый кадр после покоя не включает длину паузы. p95 считается по короткой выборке конкретного действия, с небольшим хвостом перестроения/готовности материалов.

| --- | --- | --- | --- | --- | --- |
| Атака, узкое окно | 475×664 / 2 | 712×996, авто | 23 | 33.2 / 34.2 | 2.0 |
| Розыгрыш с добором, узкое окно | 475×664 / 2 | 712×996, авто | 62 | 33.2 / 34.3 | 1.8 |
| Атака, горизонтальный breakpoint | 1280×800 / 1 | 1280×800 | 24 | 33.2 / 33.6 | 2.9 |

В этом сеансе наблюдалось примерно **30 FPS**, а не 7 FPS. Цель 60 FPS пока не подтверждена. Причина интервала около 33 ms отдельно не доказана: низкий CPU render time сам по себе не доказывает, что GPU или среда отображения не ограничивают частоту. Замеры старого браузерного сеанса с медианой около 16.7 ms нельзя использовать как строгий A/B без одинаковых условий.

При первой загрузке cold p95 доходил до 101–134 ms во время подготовки ресурсов и шейдеров. Эти кадры не выдаются за измерение прогретого боя. Основная сцена в проверенных состояниях: около 54–64 draw calls, 78–103 тысяч треугольников, 7 выбранных моделей, 0 failed models. Это меняется с героями, рукой и доской. Вся библиотека содержит 241 826 треугольников, но целиком в бой не загружается.

Отдельно проверены режимы чёткости на Retina 475×664: авто 712×996, чётче 950×1328, быстрее 475×664. Настройка меняет разрешение без перезапуска матча. После responsive-теста временное ограничение viewport снимается; остаётся реальный размер панели пользователя.

## Изменения, направленные на нагрузку

- Предметы Tripo сокращены с 3 024 650 до 241 826 треугольников во всей библиотеке, текстуры ограничены по роли. GLB 39.5 → 5.89 MB.
- В бою один renderer, общие контейнеры/геометрия/текстуры; dense GLB не участвуют в pointer picking.
- Карта теней 512 px обновляется после загрузки предметов; движение карт не пересчитывает тени всей сцены.
- Стрелка выполняет одно обновление текстуры за кадр, а не на каждое pointermove. Обычная атака не создаёт новые материалы/текстуры для цифр.
- Малые эффекты способностей берутся из пула. Новый арт перерисовывает только ожидающие его карты.
- MP4-декодирование убрано из боевого пути. Один тестовый удар — статический WebP-атлас 10 440 bytes / 12 кадров / 0.4 s, UV меняются на общем таймере.
- Покой и скрытая вкладка останавливают render loop. Пропущенные кадры не растягивают игровое действие.

## Что ещё проверять

Это не профиль всех устройств. Нужны длительный заполненный матч, средний Android/iPhone, высокий DPR и 4K, GPU timer/memory, наблюдение за нагревом. Браузерная проверка этого этапа покрывает обе композиции, наведение, выбор/удар, перетаскивание, добор, часы, ИИ, заклинание на свитке и разрешение, силы героев, меню и смену качества. Скриншоты фиксируют внешний вид; они сами по себе не доказывают плавность.

Страница пакета Flow включена в успешную production-сборку, ZIP проверен на целостность и соответствие девяти prompts реестру. Визуальную проверку новой страницы в старой вкладке выполнить не удалось: Browser Use блокирует её внутренний data:-адрес страницы ошибки. Это ограничение проверки вкладки; запуск новых Flow-клипов в бою ещё требует получения видео от пользователя.
