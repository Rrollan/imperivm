# IMPERIVM / iDos — состояние 10 октября 2026

Title **SI4IPS8B**, имя **IMPERIVM**. Пользователь создал Title и выпустил токен через платформу. Агент настроил SDK, коллекцию и загрузил самостоятельную статическую игру с текущей Babylon.js ареной, меню и конструктором. Это настоящая игра в ZIP, а не iframe вокруг Render.

## Сборка и проверка

- Текущая тестовая версия **v11**, Staged: `bld3089aa4535f64c2da9225e3c60fb9169`.
- [Запуск с конфигурацией основного Title](https://si4ips8b.idos.games/v/bld3089aa4535f64c2da9225e3c60fb9169/index.html).
- [Запуск с DEV-конфигурацией](https://si4ips8b-dev.idos.games/v/bld3089aa4535f64c2da9225e3c60fb9169/index.html).
- Загрузка выполнена с `deploy:false`. Флаг Published у каталога не означает, что эта версия стала Live. Публикация игры требует отдельного решения владельца.
- Ранее проверены гостевой вход SDK, бесплатная база, демо-пак и раздельные балансы. В v8 на реальном домене iDos проверены подготовка колод, начальная рука, два хода ИИ, рисунок обновлённого Догена, розыгрыш Стража узла и осмотр Догена в размере 844×390. Desktop — 1280×720. Ошибок/предупреждений консоли в этом прогоне нет. Проверка размеров в браузере не заменяет испытание на настоящем телефоне. Подписи кошелька, покупки и NFT mint не выполнялись.
- Текущий код прошёл `npm run test:integrations`, TypeScript, Next production build и статическую сборку iDos. Новая проверка загрузчика покрывает общий запрос, лимит четырёх загрузок, ожидание декодирования, повтор, освобождение кэша и отключённые по умолчанию подписи начала матча. Приватные пустые ID онлайн-колод исключаются из подготовки рисунков. Предыдущий engine smoke проходил; правила боя не менялись.

Первая версия (163 МБ ZIP, 607 файлов) включала неиспользуемые ассеты. v2/v3 отклонены по квоте. Владелец удалил 20 проверенных неиспользуемых файлов v1, освободив 50 МиБ, после чего **v4** (`bld52ef6b0ad13a431dbfd6d0e32421f756`) успешно загружена: **325 файлов, 57 964 136 байт после распаковки**. Копируются только ассеты, на которые ссылается клиент, включая динамические пути. Исходники и пользовательские файлы остаются в репозитории; разрешение рабочей графики не снижалось.

Проверка реальной арены обнаружила проблему canvas при загрузке изображений с отдельного CDN. Загрузчик теперь устанавливает `crossOrigin` до `src`, а изображения canvas берутся через `/v/<build>/` на домене самого Title. CSS использует абсолютные CDN-пути: относительные пути в CSS иначе разрешаются против домена stylesheet, что ломает шрифты и декорации. v5–v7 были промежуточными проверками. Для текущего боя использовать v11; старые ссылки v7 не содержат окончательных исправлений.

**Не удалять v4 из хранилища:** v8 переиспользует её 256 файлов графики, звуков и шрифтов. SHA-256 проверяется по manifest, составленному из фактического ZIP v4. Обновлённые `dogen`, `pepito`, `fud-hydra` из вложенного `cards/renewed/` отсутствовали в старой упаковке и теперь включены отдельно. v8: **70 файлов, 4 937 420 байт после распаковки** (ZIP 1 418 866 байт). Всего проверяются 259 public-ассетов и реальные пути всех карт каталога. Базовая сборка без `IDOS_PUBLIC_ASSET_BASE` самостоятельна и копирует все нужные ассеты.

В хранилище показываются только 20 крупнейших файлов; после удаления открываются следующие. Это не список мусора. Среди второго набора используются `imperivm-menu-courtyard-v1.png`, `imperivm-painted-icons-v1.png`, рамки `common/rare/epic/legendary.png` и `createArena-*.js`. Не удалять автоматически весь новый набор или файлы v4/v8. Платежи, смена тарифа и публикация не выполнялись.

## Подготовка карт и подписи

Арена ждёт рисунки исходных AI-колод и `document.fonts.ready` до показа начальной руки. Загрузки и декодирование идут по четыре, таблица и осмотр используют один запрос. Кэш держит не более 48 завершённых изображений; потребители держат нужные им изображения до закрытия. Один повтор при ошибке/таймауте, до 20 секунд на попытку, рассчитан на медленные соединения. При провале начальной подготовки показывается кнопка повторной загрузки, а не пустая игровая карта. Новые раскрытые онлайн-карты подготавливаются до полёта; закрытые ID не раскрываются и не угадываются. У загрузочного видео задержка 1,2 секунды, чтобы сначала отдать канал интерфейсу и рисункам.

Запрос подписи начала матча и раздел devnet NFT выключены по умолчанию (`NEXT_PUBLIC_PLAY_PROOF_ENABLED` включается только явным `true`; в iDos-сборке — `false`). NFT не выпущен. Вход кошельком в iDos остаётся подписью сообщения; бой с ИИ не запрашивает отдельную подпись и не тратит SOL. Аккаунт больше не запускает devnet RPC в фоне и не показывает ненужный тестовый SOL. При недоступном mainnet RPC показывается недоступность баланса, а не придуманное нулевое значение.

**Финальная сборка v9** (`blde6ac3a3aeb7744da8c4373ec409ecc68`) добавляет фильтрацию приватных ID и прогресс загрузки в онлайн-арене. iDos отклонил распаковку из-за Storage quota exceeded. Локальный ZIP готов и проверен: 70 файлов, 4 937 766 байт, ZIP 1 419 020 байт. Для повторной загрузки нужно примерно 5 МиБ свободного места. Перенос на Vercel эту квоту не исправляет: конкурсная игра остаётся размещённой на iDos.

Компактная **v10** (`bld294cb3cafe894b07a2a85020ac7031c4`) также отклонена по квоте: 66 файлов, **4 078 056 байт** после распаковки, ZIP 1 224 004 байт. Она переиспользует четыре неизменённых JS/CSS-файла из v8 по SHA-256; **v4 и v8 нужно сохранить**. Импорты локальных чанков проверены после упаковки; на домене iDos v10 ещё не проверялась, поскольку загрузка не завершилась.

Для освобождения места владелец может удалить из промежуточных v5/v6 ровно `createArena-DLm-gvAa.js`, `index-jp9U7ZWW.js`, `createArena-DpQb1EjM.js`, `index-BwP-waVk.js`: суммарно 5 366 502 байта. В ZIP v4, v8 и v10 нет ссылок на эти файлы. После удаления v5/v6 перестанут работать; рабочая v8 и общая графика сохраняются. Не удалять файлы с похожими именами или весь список крупнейших файлов. Удаление агентом не выполнялось.

После удаления владельцем старых моделей v1 (`treasury.glb`, `water-clock.glb`, `mempool-scroll.glb`; в актуальных ZIP ссылок на них нет) **v11 успешно загружена**: 66 файлов, 4 078 056 байт после распаковки, ZIP 1 224 067 байт. Статус Staged, DeployRequested=false, Errors=[]; квота больше не блокирует это обновление. Она содержит весь финальный код v10, подготовку публичных онлайн-карт и переиспользование неизменённых файлов v4/v8.

На основном домене Title в v11 проверены начальная рука, розыгрыш Легионера, два хода ИИ, рисунок Догена, перетаскивание Стража узла на поле, меню правителей, поиск Догена и осмотр карты в библиотеке. В этом прогоне ошибок и предупреждений консоли нет; отдельный запрос подписи матча отсутствует. Размер окна 1280×720. PvP, кошелёк и покупки в этом прогоне не проверялись. Отчёт упаковки и скриншот проверки сохранены приватно, исходники и этот статус отправлены в main.

## Реальный $IMP и блокировка покупок

Каноническая валюта платформы — **CryptoCurrencies.Main**, сеть **solana**. SPL mint в Solana mainnet:

[`7nfdxHzxab9UBhsZd8RCbWqDN45xJMuX33Pkpibeidos`](https://explorer.solana.com/address/7nfdxHzxab9UBhsZd8RCbWqDN45xJMuX33Pkpibeidos).

Read-only RPC подтвердил **6 decimals**, supply **1 000 000 000 IMP**, mintAuthority и freezeAuthority отсутствуют. Повторный `get_currency` 10 октября подтвердил исправление iDos: `Main.Networks[solana].Decimals=6`, `DisplayDecimals=6`, сеть/mint совпадают, депозиты, вывод и игровое списание разрешены в определении валюты. Прежний блокер `Decimals=0` устранён. Реальная покупка или депозит этим чтением не проверены; `NEXT_PUBLIC_IDOS_COMMERCE_ENABLED=false` сохраняет платежи выключенными до отдельного теста владельцем.

Клиент продолжает сверять сеть, mint, decimals, активность и право списания. Баланс Phantom, внесённый баланс iDos и локальные тестовые IMP показаны отдельно. Токены в Phantom не пополняют игровой счёт iDos автоматически.

Баланс кошелька теперь читает `GET /wallet/imp?owner=...` на том же авторитетном сервере, что и PvP. Прямой mainnet RPC с браузерным Origin iDos возвращал 403; серверный RPC вернул корректные токен-аккаунты. Endpoint использует фиксированный mint и метод, проверяет владельца/decimals, суммирует целые значения без потери точности, ограничивает параллельные запросы и кэширует результат на 15 секунд. При ошибке отображается недоступность с повтором, а не нулевой баланс. `SOLANA_MAINNET_RPC_URL` — только серверная переменная; ключ выделенного RPC не должен попадать в клиент.

Меню аккаунта сокращено и перестроено: компактное имя/адрес, две отдельные панели баланса, простые кнопки входа и обновления, ссылки на паки/историю, вторичные действия внизу. Проверено в 1280×720 и 390×844. Read-only RPC проверен на публичном адресе владельца; вход/подпись реального Phantom в агентском браузере не выполнялись.

Курс SOL/USDC, комиссия пула, доля стейкерам и остальные параметры токена не менялись. Для покупки/депозита используется штатная панель iDos; отдельные цены SOL/USDC и виртуальный обмен не применены.

## PvP и сервер

Оба режима `/play?mode=friend` и `/play?mode=random` теперь используют один авторитетный WebSocket-сервис. Случайный подбор доступен в статической iDos-игре: Next HTTP API для него не требуется. Сервер соединяет двух настоящих игроков из очереди; при отсутствии второго игрока поиск остаётся ожиданием, без подмены ботом. Поиск можно отменить, срок — пять минут. Состояние боя, скрытая рука, 75 секунд на ход и секрет восстановления такие же, как в игре с другом.

Код сервера автоматически добавляет точные origin `https://si4ips8b.idos.games` и `https://si4ips8b-dev.idos.games` к существующему ALLOWED_ORIGINS. Маски доменов не используются; после обновления сервера оба домена допускаются для WS и read-only баланса. Для платных карт отдельно нужны серверные переменные:

```dotenv
IDOS_TITLE_ID=SI4IPS8B
IDOS_COLLECTION_ID=IMPERIVM_AGORA
# При необходимости — HTTPS endpoint выделенного RPC, только на сервере:
# SOLANA_MAINNET_RPC_URL=https://...
```

Проверены реальные два WS-клиента: подбор, скрытая рука, ход, отмена, истечение очереди, одинаковые имена и секреты восстановления, отмена во время проверки коллекции. В интерфейсе двух вкладок проверены подбор, стартовые руки, розыгрыш карты, перезагрузка и сдача. Серверный прогон: 18 тестов. Локальный серверный endpoint вернул правильный IMP баланс с разрешённым Origin.

Режим денежных ставок **не реализован**: нет хранения двух ставок, выплаты победителю и возврата при сбое. Конфигурация Main сама по себе не создаёт платный PvP. До реализации нельзя принимать ставки. Контрольный список: [multiplayer-readiness.md](../multiplayer-readiness.md). Комнаты и очередь сейчас в памяти одного процесса; рестарт стирает их, поэтому такой транспорт предназначен для бесплатных дуэлей.

Title Blockchain.IframeConnectHosts разрешает API iDos, Render HTTP/WS и Solana RPC. Это не заменяет проверку Origin на сервере.

## Воспроизводимая сборка

```sh
npm ci --legacy-peer-deps
npm run test:integrations
npm run smoke
npm run build
IDOS_ASSET_BASE='https://static.idos.games/drive/app/SI4IPS8B/v/<build_id>/' npm run build:idos
cd dist/idos
zip -qr ../imperivm-idos-SI4IPS8B.zip .
```

Получить build_id/AssetBase через begin_build_upload. ZIP содержит index.html в корне, ассеты и шрифты текущего интерфейса; `.env`, ключи, сессии и неотслеживаемые пользовательские Flow-файлы не копируются. Подписанный upload URL хранить приватно, не коммитить. finish_build_upload использовать с deploy:false до финальной проверки. Для локального preview допускается IDOS_ASSET_BASE=http://127.0.0.1:3113/.

Если неизменённая графика уже загружена в известной версии этого же Title, можно избежать дублирования:

```sh
IDOS_ASSET_BASE='https://static.idos.games/drive/app/SI4IPS8B/v/<new_build_id>/' \
IDOS_PUBLIC_ASSET_BASE='/v/bld52ef6b0ad13a431dbfd6d0e32421f756/' \
IDOS_SHARED_CODE_MANIFEST='platform/idos/shared-code.v8.json' npm run build:idos
```

В таком режиме ZIP содержит изменённый код и новые/изменённые группы ассетов. Проверенные неизменённые группы остаются в v4; сравнение выполняется по `platform/idos/shared-assets.v4.json`. Неизменённые JS/CSS остаются в v8 только при совпадении SHA-256 с `platform/idos/shared-code.v8.json`; изменённые чанки включаются в новый ZIP. Отчёт — `dist/idos-assets-report.json`. Динамическая группа переиспользуется только при совпадении всех её файлов. Обе исходные версии нужно сохранить. Для сборки без переиспользования кода опустить IDOS_SHARED_CODE_MANIFEST.

## Перед выпуском

1. Финальная v11 успешно Staged. Сохранить v4 с переиспользуемыми ассетами и v8 с переиспользуемым кодом. Main.Decimals=6 уже подтверждены readback; проверить единицы внесённого игрового баланса. Реальная покупка — только по решению владельца и с его подтверждением кошельком.
2. Развернуть обновлённый WS-сервис; `/health` должен содержать `random-pvp` и `imp-balance`. Затем проверить две вкладки и баланс на домене iDos.
3. В панели Title исправить **Type App / Category tools** на игровую категорию. Соответствующий редактор метаданных не доступен в подключённом MCP.
4. Владелец проверяет вход своим кошельком, разделение балансов и повторный вход. Публикация и платежи не выполняются этим тестом автоматически.
5. Next 14.2.35 и вложенный postcss имеют advisories по npm audit. Статическая iDos-сборка не запускает Next server; перед следующим Render/Next-деплоем нужен отдельный совместимый upgrade. Не применять audit fix --force без проверки React/Babylon/R3F.
6. После публикации проверить страницу каталога, обновить подтверждённые факты в заявке и приложить реальные demo/pitch-видео. Финальные Colosseum/Earn submit остаются у владельца.
