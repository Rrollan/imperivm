## Текущие ограничения и локальное исправление

Read-only MCP `list_my_titles`, `get_blockchain`, `get_currency` подтвердил live Title `SI4IPS8B`: WalletLogin включён; Main/solana Active; депозиты и вывод включены; `MinAccountAgeDays=7`; комиссия вывода Main 6%. Возраст конкретного аккаунта по этой конфигурации установить нельзя. Срок и комиссию не меняли.

Исходник `ImpPurchasePanel.tsx` намеренно отключал Jupiter при `idos.embedded` и предлагал ссылку на отдельную игру. Установленный SDK `@idosgames/wallet 0.6.3` требует нативную панель родительского сайта для депозитов/вывода. Проверенная актуальная версия 0.6.4 также предоставляет `openPlatformWalletPanel()`, но не документирует мост для произвольной подписи Jupiter или выбора Buy/Sell. Добавление выдуманного postMessage или простое снятие проверки iframe не обеспечит рабочий обмен.

Официальный `@idosgames/core 0.21.3` восстанавливает Wallet по refresh token. Увиденное сообщение появляется при неудачной ротации/отсутствии пригодного токена, после которой Wallet нельзя безопасно воспроизвести. Само сообщение не отличает истечение токена от временного сбоя refresh. Поэтому нельзя автоматически стереть сохранённую сессию или молча заменить её гостевым аккаунтом.

Подготовлено локально:

1. В режиме iDos основной путь покупки объясняет **Buy/Sell на текущей странице**, без переноса игрока в отдельную вкладку. Jupiter сохраняется для прямого запуска игры.
2. «Повторить» при ошибке входа вызывает повтор восстановления входа. Раньше он обновлял несуществующий gateway коллекции и ничего не делал.
3. При известном отказе восстановления Wallet показан понятный текст и кнопка **«Войти кошельком»**. Её действие использует существующую проверку свежего сообщения. Неудачный refresh не превращает кешированный адрес в авторизованный аккаунт и не очищает credentials.
4. Встроенный блок переводов явно называется **«Пополнение и вывод IMP»** и объясняет выбор Deposit/Withdraw и ввод суммы.

Это исправляет маршрут и восстановление после ошибки. Это не доказательство успешной сделки в правом блоке iDos или успешного вывода. Для отказа вывода нужен фактический ответ интерфейса; 7-дневное правило пока является возможной причиной, а не установленной.

Локальная проверка: TypeScript (`tsc --noEmit --incremental false`), существующие `session.test.ts` и `impPurchase.test.ts`, `git diff --check` завершились успешно. Они не запрашивали подписи и не выполняли сделки. Кадры записи сохранены в игнорируемой директории `verification/idos-wallet-20261013/`. Новый production build и живой выпуск этой правки ещё не выполнялись.

## Конкретный источник повторяемости в нашем коде

Обычная iDos-тренировка вызывает `ArenaEntry` без `seed`/`opponent`. `ArenaLab` и `createLabGame` по умолчанию используют seed **2718**. Кнопка «Ещё один бой» использует тот же seed; соперник обычно Degen, либо Whale против Degen. AI — детерминированная жадная эвристика. При одинаковой колоде и действиях игрока старт и ответы повторяются.

Первое улучшение после согласования: новый seed для каждого обычного матча, разнообразные бесплатные соперники и три поведения бота — давление, контроль указов, развитие ресурсов. Фиксированные seed оставить для диагностики и задач. AI должен принимать решения по доступной ему информации, без чтения скрытой руки игрока. Это полезнее, чем сразу добавлять десятки новых карт.

## Предлагаемый первый режим: «Римский поход»

**Игрок собирает необычную стратегию и ведёт её через три разных боя к боссу.** Режим доступен сразу, поэтому его можно играть, когда в PvP ещё мало людей.

Цикл: выбрать предводителя и один из трёх стартовых планов → бой → выбрать одно из трёх усилений → следующий бой с новым противником → финальный босс → результат с собранной стратегией → новый поход.

Первая версия:

- Три последовательных PvE-боя: агрессивный противник, защитник с гарнизоном, босс указов. Перед каждым боем виден его особый закон.
- Три набора колод на существующих картах: легион/защита, Сенат/указы, быстрые фракционные комбинации.
- Шесть ограниченных реликвий, предлагаемых по три между боями. Примеры для балансировки: первый боец за ход получает +1 к атаке; первый отложенный указ за ход дешевле на 1, но не ниже 1; первый боец в матче получает +2 здоровья.
- Усиления действуют только в походе. `CARDS`, личная коллекция и обычный PvP не получают постоянных изменений.
- Сохранение похода, возможность продолжить после закрытия страницы, кнопка нового забега. Награда — результат и косметическое достижение; реальная экономика IMP этим режимом не затрагивается.
- Цель по длительности отдельного боя — 3–5 минут; её надо подтвердить игровыми сессиями. Это проектная цель, не обещание результата.

Почему это может удерживать: после победы возникает содержательный выбор, а следующая битва проверяет выбранную комбинацию. Повторный запуск даёт другую стратегию. Это также создаёт материал для роликов: «эту связку я собрал только в этом походе».

Техническая граница: отдельный `expedition-v1` ruleset и состояние забега; обычные правила остаются `classic-v1`. Эффекты применяются через движок, а не нарисованные без реального действия бонусы. Проверять влияние реликвий, завершение/восстановление забега и изоляцию от коллекции.

## Следующие кандидаты

| Идея | Как играет человек | Объём и порядок |
| --- | --- | --- |
| **«Последний указ» — тактические задачи** | Готовая позиция: спасти казну, отменить RUG PULL или победить за ход. Подсказка после попытки, ссылка на ту же задачу для друга | Небольшая первая серия из 8–10 проверяемых задач. Хороший второй шаг и контент для соцсетей |
| **«Закон Сената»** | Перед матчем показано одно симметричное правило, меняющее выбор колоды и темп. Игрок знает его заранее | Ограниченный режим с 4–6 правилами. Не включать новые законы автоматически в обычный PvP |
| **Мастерство предводителя** | Отмечаются освоенные сочетания, появляются титулы и оформление карт/профиля | После нового игрового цикла. Косметические награды, понятные цели, без прибавки силы за накопленный XP |
| **«Захват Рима»** | Три района, победа за контроль двух, ограниченное число раундов | Крупный отдельный режим: новая расстановка, разрешение действий, AI, победа и мобильный стол. Рассматривать после первой версии похода |

«Захват Рима» ближе к пространственной игре Snap, но это гораздо больше изменений, чем внешний вид трёх локаций. Для первого обновления рекомендую **разнообразие обычной тренировки + Римский поход**; задачи можно добавить следующей небольшой серией.

## Как оценить результат

Отдельно смотреть: сколько новых игроков заканчивают первый бой, сколько нажимают «Ещё один бой», сколько завершают поход и возвращаются. Длительность матча и причины выхода также важны. Сравнивать с исходной версией после достаточного числа реальных сессий; количество лайков проекта само по себе не показывает, стало ли играть интереснее.

## Что остаётся согласовать

Выбор нового режима и его первая версия. Для вывода IMP — точный отказ, возраст именно игрового аккаунта и, при наличии, статус уже созданной операции. До этого вывод нельзя объявить проверенным или исправленным.
