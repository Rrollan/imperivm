# IMPERIVM: интерфейс, боевой отклик и телефон

7 октября 2026. Референсы помогают выбрать приёмы, а не заменить наш художественный стиль. Правила, баланс и авторитетный сетевой сервер в этой итерации сохранены.

## Что изучено

- Hearthstone: использованы ранее сохранённые разборы в `hearthstone-ux-audit-20261005.md` и `hearthstone-system-analysis-20261006.md`, повторно проверены официальные материалы. Его удобство для нас — ясные стоимость/статы, крупное рассмотрение карты, подсветка доступного действия, видимый выбранный противник и однозначный момент результата. Это дизайнерские выводы; численные тайминги IMPERIVM не являются измерениями Hearthstone. [Официальный сайт](https://hearthstone.blizzard.com/en-us/).
- [Duelyst.gg](https://duelyst.gg/): в браузере просмотрены стартовый экран, панель обновления и вход. Иллюстрация окружает спокойную тёмную панель; основная кнопка выделяется светом и рамкой. До матча не дошли: требуется аккаунт. Регистрацию не выполняли.
- [OpenDuelyst](https://github.com/open-duelyst/duelyst): открытый код карточной тактики для браузера, включая мобильные браузеры. Полезен как пример отдельного игрового SDK и слоя представления; поднимать его Firebase/Docker-окружение для наших эффектов не требуется.
- [HearthSim/Joust](https://github.com/HearthSim/joust): браузерное воспроизведение Hearthstone, а не готовый сетевой движок для нашей игры. Полезен принцип последовательного воспроизведения событий. Его старые зависимости и художественные ресурсы Blizzard не перенесены.
- [Дневник Duelyst II](https://news.duelyst2.com/updates-from-mythron-october-2023/): разработчики описывают общий JavaScript SDK для разных клиентов, затем отдельную работу над анимациями, меню и историей. Это поддерживает наш подход: исход боя вычисляется движком, визуальный контакт его показывает.

## Принятые решения

| Проблема IMPERIVM | Реализованный приём | Причина |
|---|---|---|
| Серый текст на пёстром мраморе | Тёмный зал, светлая типографика, бордовые выбранные действия, бронзовые края | Текст и состояние кнопки читаются без расшифровки текстуры |
| Карта теряется в меню | Одна исходная карточная поверхность в каталоге и рассмотрении; рядом описание | Игрок узнаёт свою карту и видит правило целиком |
| Все атакуют одинаково | Ближний бой, магия жрецов/министров, болты инженеров | Роль считывается по способу действия |
| Попадание звучит дважды | Один профиль оружия на контакт; общий звук урона не накладывается на него | Менее шумный и понятный отклик |
| Медальоны перекрывают резной край | Измерение внутреннего паза и проекция 1586×992 → 1600×1000 | У портрета и рисунка доски одна геометрия |
| Маленькие действия на телефоне | Минимальная зона нажатия 44 CSS px независимо от размера рисунка | Деталь остаётся частью доски, но по ней можно попасть |
| Вертикальный стол слишком мелкий | Бой в горизонтальном положении; меню и библиотека в обоих | Поле, рука и противник остаются видимыми одновременно |
| Сложно прочитать карту горизонтально | Карта и правило рядом, кнопка снизу, окно ограничено высотой | Не приходится закрывать описание, чтобы найти действие |

Атаки используют существующий общий Babylon-рендерер. Снаряды и следы заранее создаются в пуле и переиспользуются; текстуры не создаются на каждом попадании. Магическая атака не меняет правила ответного урона. Reduced motion убирает снаряды и движение атакующего; звук и вибрация имеют отдельные настройки. Вибрация работает только там, где браузер предоставляет `navigator.vibrate`.

## Дальнейшая художественная запись звуков

Текущий комплект — программный, локальный, без загрузки внешнего аудио. Для замены на записанные материалы нужен единый набор 48 kHz WAV, mono, без музыкального фона и длинного хвоста. Максимум −3 dBTP, согласованная воспринимаемая громкость; варианты одного действия не должны отличаться по уровню больше 1 dB.

| Файл | Длительность | Задание звукорежиссёру / генератору |
|---|---:|---|
| `ui-wood.wav` | 60–90 ms | Soft walnut latch, close dry contact, restrained bronze edge, no digital beep |
| `card-place.wav` | 150–220 ms | Thick parchment sliding onto polished wood, gentle weighted landing, no voice |
| `steel-hit.wav` | 180–260 ms | Short Roman blade contact with shield, woody body and restrained metal partials, no shrill ringing |
| `arcane-hit.wav` | 250–350 ms | Focused emerald/violet magic pulse, airy attack and descending crystalline tail, no explosion |
| `bolt-hit.wav` | 150–220 ms | Compact mechanical energy bolt, quick air cut then solid wooden impact, no laser-game beep |
| `turn-seal.wav` | 200–300 ms | Bronze seal touching a wooden command tablet, low bell resonance, clear restrained finish |

Для текущих векторных снарядов новый видеопак не нужен: они движутся между реальными позициями фигур, сохраняют резкость при масштабировании и не маскируют карту прямоугольником видео. Существующий START/END/PROMPT-пак 01–17 и установленные эффекты остаются в `/arena-lab/animation-kit`.
