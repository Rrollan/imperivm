# Реальный PvP: текущая реализация и граница запуска

`/play?mode=friend` создаёт закрытый стол с одноразовым приглашением на второе место. `/play?mode=random` ставит гостя в настоящую очередь: при отсутствии второго игрока бой не начинается. `/play?mode=ai` ведёт на существующую арену с заменой стартовых карт. Все четыре готовые колоды бесплатны; кошелёк и NFT не требуются.

Гостевая сессия сохраняется в HTTPOnly cookie на шесть часов и переживает обновление страницы, переход в библиотеку и главный зал. Другу нужно открыть приглашение в другом браузере или на другом устройстве. Две обычные вкладки одного браузерного профиля представляют одного гостя; повторный переход по своей ссылке не создаёт второго игрока.

## Сервер является авторитетом

- Клиент отправляет только действие, ID комнаты и ожидаемую ревизию. Сервер проверяет членство, очередь хода и применяет общий `applyAction` на своём состоянии. Никакие клиентские HP, урон, результат или RNG не принимаются.
- Каждому месту выдаётся собственная проекция: своя рука, размеры обеих колод и чужой руки, открытые бойцы, казны, ресурсы и ожидающие указы. Порядок колод, чужие карты/UID в руке, RNG и сырой `GameState` никогда не сериализуются. Легальные действия выдаются только активному владельцу места.
- История строится из публичных действий, а не пересылает сырой журнал движка. Стартовая замена показывает число заменённых карт.
- Сервер случайно распределяет первый ход между приглашёнными / подобранными игроками. Он фиксирует готовые колоды и `classic-v1`; пользователь не присылает колоду или seed.
- Конфликт ревизий возвращает 409; интерфейс обновляет состояние и просит повторить действие. Потеря ответа не автоматически повторяет мутацию.
- POST проверяет точный Origin, JSON, allowlist полей и предел тела 8 KiB, включая chunked-запросы. Cookie: HTTPOnly, SameSite=Strict, Secure для HTTPS. Чтение выдаёт no-store/private, авторизационные ошибки не раскрывают чужое состояние или stack trace.

## Время, отмена, переподключение

Приглашение действует 10 минут, очередь — 5 минут. Один гость не может одновременно находиться в нескольких столах. Ожидающий стол/поиск можно отменить. Активный бой покидают явной сдачей с подтверждением в UI; закрытие вкладки не немедленное поражение. Неактивный клиент получает 150 секунд на возврат. После паузы обоих — ничья. Сервер оценивает просроченные сроки при следующем обращении, поэтому в пустом процессе нет таймеров, имитирующих играющего человека.

Ход ограничен 90 секундами. При истечении сервер сохраняет стартовую руку, если ещё открыта замена, и передаёт ход легальным действием движка. Бой хранится до часа, результат — 15 минут. Неактивные комнаты и сессии удаляются. Есть ограничения: 2000 сессий, 500 комнат, 100 новых сессий на процесс в минуту, 60 мутаций и 90 чтений в минуту на сессию. Это защита от случайного штормового клиента; для публичного сервиса нужна защита на доверенном ingress по IP, без доверия произвольному X-Forwarded-For.

Интерфейс обновляет состояние раз в 2,5 секунды. Он использует существующие лица карт, отдельные действия стейкинга, подсветку допустимых целей, клавиатурный просмотр способностей и настоящие эффекты атласов на наблюдаемых изменениях здоровья/атаки. Рост максимума здоровья показывается усилением, не лечением. Онлайн-поле сейчас отдельный DOM-рендерер; полное перенесение физического 3D-представления и плавного проигрывания каждого промежуточного действия — следующий этап. Эта версия не притворяется, что это уже сетевой `GameSession` Babylon.

## Что можно запустить сейчас

Один постоянно работающий Node `next start` с HTTPS и корректным публичным Origin. `MULTIPLAYER_PUBLIC_ORIGIN=https://game.example.com` должен точно совпадать с origin страницы, без завершающего `/`. При прямой локальной разработке переменную оставляют пустой, origin берётся из URL Next-запроса. Обратный прокси обязан передавать доверенный host и HTTPS-адрес; не публикуйте произвольный Host-header origin как доверенную настройку.

`GET /api/multiplayer/health` проверяет живость и версию протокола. Это не проверка доступности долговременного хранилища. Рестарт Node стирает комнаты и гостевые сессии: UI предлагает переподключиться. Для локального теста это допустимо, для обещания публичного продакшена — **блокер**.

## До публичного продакшена

1. Перенести комнаты, очередь, hash гостевых сессий и ревизии в долговременное транзакционное хранилище. Сопоставление очереди и compare-and-swap действия должны быть атомарными между процессами. `globalThis` не является распределённым хранилищем.
2. Добавить доверенный ingress, HTTPS, rate limits по IP и наблюдение за ошибками/задержкой. Cookie не использовать как платёжный или аккаунтный credential.
3. Добавить интеграционный прогон через два узла, восстановление после рестарта и проверку времени при отключении обоих клиентов. Serverless и несколько реплик без shared storage сейчас **не поддерживаются**.
4. Проверить PvP баланс на реальных людях. Текущая очередь FIFO по доступности, без выдуманного рейтинга, ботов в случайном режиме или обещаний сбалансированных матчей по MMR.

## Проверка

`node --import tsx scripts/multiplayer-check.ts` проверяет независимые гости, invite/self-join, скрытую информацию, нелегальные чужие действия, очередность, настоящие ходы/атаки, ревизии, отмену, таймауты, отключение и валидацию входа.

`node --import tsx scripts/multiplayer-check.ts http://127.0.0.1:3101` дополнительно проверяет HTTP с отдельными cookie jars, флаги cookie, Origin/CSRF, Content-Type, payload limit, реальные комнаты/случайный подбор и health endpoint.

Skill `security-audit` применён для проверки новой авторизации/API. CLI `@claude-flow/cli` не входит в зависимости; новые пакеты для аудита не устанавливались. Выполнены ручное моделирование угроз и регрессионные проверки границы протокола, без утверждения о завершённом независимом pentest.
