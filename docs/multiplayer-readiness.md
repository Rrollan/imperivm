# PvP и денежный режим: готовность

`/play?mode=friend` и `/play?mode=random` используют авторитетный WebSocket-сервис из `server/`. Оба работают в самостоятельной статической iDos-сборке. `/arena-lab` — бесплатная тренировка с ИИ. Бесплатные колоды не требуют кошелька, NFT или SOL.

## Бесплатный PvP

Комната с другом выдаёт шестизначный код. Случайный подбор соединяет двух настоящих ожидающих игроков FIFO, без рейтинга и подмены ботом. Если второго игрока нет, показывается ожидание. Поиск можно отменить; отключённый клиент снимается из очереди, срок ожидания — пять минут.

Сервер использует общий движок, проверяет колоду, очередь хода, действия и ревизию. Персональные снимки показывают свою руку, публичных бойцов и размеры чужой руки/колод; чужая рука, порядок колод и RNG скрыты. Владение платными Agora-картами и правителями проверяется по серверной коллекции iDos, клиентский localStorage не является доказательством.

Онлайн-поле использует текущую Babylon.js арену, подготовку рисунков перед появлением новых публичных карт, стартовую замену и общий таймер 75 секунд. Розыгрыш карты не продлевает ход. При потере связи действия блокируются; после восстановления приходит актуальный снимок, ранее отправленные действия не повторяются автоматически.

Секрет места хранится в `sessionStorage`, не попадает в ссылку приглашения или снимки соперника. Обновление вкладки возвращает игрока в матч. Даже при одинаковых отображаемых именах место определяется секретом. Копия вкладки может унаследовать её сессию; для независимого игрока открывают новую вкладку или другое устройство.

Ограничение: комнаты и очередь находятся в памяти одного Node-процесса. Рестарт стирает их. Отключение обоих занявших места игроков удаляет комнату; одиночный обрыв позволяет вернуться, пока соперник подключён. Неактивные комнаты удаляются через 30 минут; пинги не продлевают их жизнь. Это допустимо для бесплатного MVP и недостаточно для денежных ставок.

Автоматические проверки `npm test --prefix server`: 21 тест, настоящие WS-клиенты, полный матч, скрытая рука, нелегальные ходы, 10-секундный обрыв, таймер, случайный подбор, отмена/истечение очереди, одинаковые имена, отмена во время проверки коллекции, фиксированный RPC баланс и Origin. Дополнительные проверки RPC-релея покрывают allowlist методов, запрет произвольного upstream и batch-запросов, отказ от неподписанного пакета и обхода preflight, точный Origin, лимит тела и сохранение ошибки upstream. В двух вкладках ранее проверены подбор, начальная рука, розыгрыш, перезагрузка и сдача — локально и на домене iDos v12 с production WS; v13 сохранила тот же функциональный PvP-код. Тесты не списывали средства.

Production использует WSS и точный Origin allowlist. Предыдущая проверка 10 октября Render `/health` подтвердила `status:ok`, `random-pvp`, `imp-balance` и версию `23bcd2d78d72`; это историческая проверка до добавления транзакционного RPC-релея. Текущий код также объявляет `wallet-rpc` и явное `paidPvp.enabled:false`; наличие нового кода на live сервере проверяют по версии health после развёртывания. Порядок запуска и переменные: [server/README.md](../server/README.md). Существующий Next HTTP API остаётся для совместимости старых клиентов; текущий случайный режим его не вызывает.

## IMP и режим на деньги

Реальный токен IMP находится в Solana mainnet. Каноническое определение iDos `Main` теперь имеет правильные 6 decimals. Phantom-баланс и внесённый игровой баланс iDos — разные счета. Чтение публичного кошелька работает через фиксированный read-only endpoint WS-сервера; при ошибке UI показывает недоступность, не придуманный ноль.

В клиенте добавлена инфраструктура внесения IMP из Phantom в официальный пул iDos и вывода обратно. Вход кошельком сам по себе ничего не переводит. Перед операцией перечитываются mint, decimals, разрешения и адрес пула; сумму игрок подтверждает отдельно в Phantom. Чек сохраняется до отправки, повторная операция блокируется до выяснения исхода, вывод восстанавливается по первоначальному `titleTransactionID`, а внесение — по той же подписи транзакции. Запрос с неопределённым результатом не считается неудачным только из-за таймаута.

Серверный `POST /wallet/rpc` проксирует только ограниченный набор Solana RPC-методов к фиксированному mainnet upstream. Требуются точный разрешённый Origin и ограниченные параметры; пользователь не задаёт URL RPC. `sendTransaction` передаёт уже подписанный кошельком пакет с обязательным preflight; сервер не хранит ключ и не подписывает транзакции. Это транспорт внесения/вывода, а не механизм расчётов PvP.

Клиентские проверки внесения/вывода выполнены с mock RPC, mock кошельком и декодированием Solana wire: точность 6 decimals, привязка аккаунта/mint, разрешения, восстановление чека, однократный отчёт о внесении, повтор вывода без второго списания, блокировка неоднозначного исхода. Реального внесения или вывода владельцем эти тесты не выполняли и не подтверждают.

**Денежный PvP остаётся выключенным.** Точный блокер — нет проверенного iDos API, который атомарно удерживает средства двух участников нашего TCG, затем принимает результат внешнего авторитетного WS-сервера и однократно выполняет выплату либо возврат. Нативный iDos Match рассчитывает собственный мгновенный бой персонажей и не предоставляет документированного метода расчёта по результату нашей карточной арены. `CloudCode.ResourcePolicy` не доказывает наличие такого API. Подробности и готовый вопрос платформе: [аудит commerce API](idos/commerce-api-audit-20261010.md).

Создание токена, подключение кошелька, внесение IMP и покупка паков не создают ставки. Игровое действие `stake` закрепляет бойца в гарнизоне и не переводит IMP. Сейчас нельзя принимать ставки или обещать выплату за победу.

Для реализации нужны:

1. Согласованные правила: валюта, размер ставки, комиссия, ничья, сдача, таймаут и возврат. До согласования нет скрытого денежного режима.
2. Транзакционное долговременное хранилище матчей, аккаунтов, двух ставок и расчётов. Запись двух удержаний атомарна; повторный запрос не списывает повторно.
3. Проверенный механизм удержания/эскроу и выплаты именно для внешнего TCG: подтверждение удержания средств обоих игроков до старта, однократный расчёт по авторитетному результату, возврат при отмене/сбое, восстановление после рестарта. Нужны точные API reserve/query/settle/refund с idempotency и атомарными гарантиями; видимый `EntryCost` сам по себе этого не обеспечивает.
4. Авторизация аккаунта для денежного матча, серверная проверка баланса/владения, защита от повторных запросов и изменения суммы клиентом. Бесплатное имя/секрет комнаты не являются платёжным credential.
5. Тесты в неплатёжной среде: одновременные действия, повтор, рестарт, один не внёс ставку, отключения, ничья, ошибка выплаты, возврат, точность 6 decimals. Затем отдельный минимальный реальный тест владельцем с подтверждениями кошелька.

Флаг покупок паков и готовность денежных матчей — отдельные условия. Денежный режим остаётся выключенным независимо от подключения кошелька и доступности внесения IMP. Реальные транзакции тестами этого обновления не выполнялись; их проверяет владелец с явным подтверждением суммы в кошельке.
