# IMPERIVM: WebSocket-сервис своих игр

Отдельный авторитетный Node-сервис для бесплатных матчей 1-на-1. Игрок создаёт комнату, получает шестизначный код и передаёт его другу. Оба клиента отправляют намерения; сервер проверяет их общим движком и рассылает персональные снимки состояния. Баланс и правила карт остаются в `lib/engine/` и `lib/cards.ts`.

Ставки `$RUG`, дуэли на карту, платежи и ончейн-эскроу в этот сервис не входят. Игровое действие стейкинга бойца сохраняется как существующая механика боя и не является денежной ставкой.

## Запуск локально

Нужен Node.js 22 или новее. Команды ниже выполняются из корня репозитория `imperivm-design`.

Установить зависимости сервера:

```sh
npm ci --prefix server
```

Терминал 1 — сервис с перезапуском при изменении исходников:

```sh
npm run dev --prefix server
```

Сервис слушает `0.0.0.0:3102`. Проверка живости:

```sh
curl http://127.0.0.1:3102/health
```

Терминал 2 — интерфейс игры:

```sh
npm ci
NEXT_PUBLIC_WS_URL=ws://127.0.0.1:3102 npm run dev -- -p 3101
```

Или добавить строку `NEXT_PUBLIC_WS_URL=ws://127.0.0.1:3102` в корневой `.env.local` и перезапустить Next.js. Для собранного интерфейса переменная должна быть задана **до** `npm run build`: `NEXT_PUBLIC_`-значения встраиваются в клиентский код.

Чтобы запустить собранный сервер вместо watch-режима:

```sh
npm run build --prefix server
npm start --prefix server
```

Сервис собирает общий движок вместе со своими исходниками. Отдельная сборка Next.js и установка браузерных зависимостей для запуска сервера не требуются.

## Два игрока в браузере

1. Открыть `http://127.0.0.1:3101/play?mode=friend` в двух обычных вкладках либо на двух устройствах.
2. В первой вкладке указать имя, выбрать предводителя и создать комнату. Скопировать код из шести символов; до входа второго игрока будет видно ожидание соперника.
3. Во второй вкладке указать другое имя, выбрать предводителя и ввести тот же код. Ссылка приглашения тоже содержит только публичный код комнаты.
4. Завершить замену стартовых карт, затем по очереди разыгрывать карты, атаковать и заканчивать ход. Обе стороны видят изменения сразу после подтверждения сервером.
5. Доиграть до победы. Оба клиента должны получить одинаковый результат; рука соперника остаётся скрытой.

Место и секрет восстановления хранятся в `sessionStorage` вкладки. Обычные независимые вкладки могут быть разными игроками; копия вкладки может унаследовать её сессию. Для надёжного теста создайте вторую новую вкладку и укажите другое имя либо используйте приватное окно.

### Проверка обрыва на 10 секунд

Во время матча отключить сеть одного клиента на 10 секунд, затем включить её. В отключённой вкладке должно появиться «Переподключение…», действия заблокируются. После восстановления клиент повторно отправит `join` со своим именем и секретом, получит актуальный снимок и продолжит тот же матч. Пропущенные действия автоматически не повторяются.

Можно также обновить одну вкладку: её `sessionStorage` сохраняется при перезагрузке. Новый браузер без секрета не получает чужое место по одному известному имени.

### Проверка нелегального хода

Автоматический сетевой прогон использует настоящие WebSocket-клиенты: полный матч, восстановление после обрыва, чужой атакующий, чужая очередь хода и приватность снимков:

```sh
npm test --prefix server
```

При отклонённом ходе сервер отправляет `error`, пишет причину в лог и сохраняет прежнее состояние. `cardId` при атаке должен быть UID своего бойца, готового к атаке; UID чужого бойца не даёт управления им.

### Телефон и компьютер в одной сети

`127.0.0.1` на телефоне указывает на сам телефон. Используйте локальный IP компьютера, например `192.168.1.50`, и запустите сервис с разрешёнными origin обеих страниц:

```sh
ALLOWED_ORIGINS=http://192.168.1.50:3101,http://127.0.0.1:3101 npm run dev --prefix server
```

Интерфейс запустить с адресом сервера, доступным телефону:

```sh
NEXT_PUBLIC_WS_URL=ws://192.168.1.50:3102 npm run dev -- -H 0.0.0.0 -p 3101
```

Открыть `http://192.168.1.50:3101/play?mode=friend` на обоих устройствах. Разрешить входящие подключения к портам 3101 и 3102 в локальном брандмауэре.

## Переменные окружения

| Переменная | Где задаётся | Значение |
| --- | --- | --- |
| `PORT` | WS-сервис | Порт HTTP и WS; локально по умолчанию `3102`. На Render используется предоставленный платформой порт. |
| `ALLOWED_ORIGINS` | WS-сервис | Точные origin страниц игры через запятую, включая схему и порт, без пути и завершающего `/`. Для production задаётся явно. |
| `NODE_ENV` | WS-сервис | `production` при запуске опубликованного сервиса. |
| `NEXT_PUBLIC_WS_URL` | Next.js / Vercel | Локально `ws://127.0.0.1:3102`, для HTTPS-сайта — `wss://<сервис>.onrender.com`. |

Origin страницы и адрес WS-сервиса — разные значения. Например, `ALLOWED_ORIGINS=https://imperivm.example.com`, а `NEXT_PUBLIC_WS_URL=wss://imperivm-ws.onrender.com`. Preview-домен Vercel добавляется в allowlist отдельно; маска `*.vercel.app` не используется.

## Render: Free Web Service

Создать **Web Service** с репозиторием `Rrollan/imperivm` и веткой `rebirth`:

| Настройка Render | Значение |
| --- | --- |
| Language / Runtime | Node |
| Branch | `rebirth` |
| Root Directory | Оставить пустым, то есть корень репозитория |
| Build Command | `npm ci --prefix server && npm run build --prefix server` |
| Start Command | `npm start --prefix server` |
| Instance Type | Free |
| Health Check Path | `/health` |
| Environment | `NODE_ENV=production`, `ALLOWED_ORIGINS=https://<домен-интерфейса>`, `NODE_VERSION=22` |

Root Directory нельзя ставить в `server`: сервис импортирует общий `lib/engine`, а Render исключает файлы вне указанного корня. [Документация monorepo Render](https://render.com/docs/monorepo-support).

`PORT` вручную задавать не нужно. HTTP health endpoint и WebSocket используют один сервер на `0.0.0.0`; Render предоставляет порт и TLS. [Настройка Web Service](https://render.com/docs/web-services).

После успешного запуска проверить `https://<сервис>.onrender.com/health`. Публичный адрес подключения клиентов — `wss://<сервис>.onrender.com`, без `/health`. Render принимает WebSocket; для публичного подключения используется `wss`. [WebSocket на Render](https://render.com/docs/websocket).

**Ограничение этой итерации:** комнаты находятся в памяти одного процесса. Рестарт, новое развёртывание или остановка сервиса стирают матчи. На Free сервис засыпает после 15 минут без входящего HTTP/WS-трафика; запуск после сна может занять около минуты. Render также может перезапустить Free-сервис. Это подходит для бесплатных тестовых матчей, но не обеспечивает сохранение незавершённых игр при перезапуске. [Ограничения Free](https://render.com/docs/free).

Использовать один экземпляр. Несколько независимых экземпляров не разделяют `Map` комнат, а балансировщик Render может направить реконнект на другой экземпляр. Для масштабирования и сохранения матчей потребуется общее хранилище и согласование действий между процессами. [Реконнект и экземпляры Render](https://render.com/docs/websocket).

## Vercel: подключить интерфейс

В настройках проекта Vercel → Environment Variables добавить для нужного окружения:

```dotenv
NEXT_PUBLIC_WS_URL=wss://<сервис>.onrender.com
```

В `ALLOWED_ORIGINS` Render указать точный домен этого интерфейса, например `https://imperivm.vercel.app`. Затем пересобрать / redeploy интерфейс на Vercel: изменение переменной не меняет уже собранные deployments. [Переменные окружения Vercel](https://vercel.com/docs/environment-variables).

На HTTPS-странице адрес `ws://` будет заблокирован браузером как небезопасное соединение. Для опубликованной игры нужен `wss://`.

## Протокол и авторитет

Источник типов — `lib/net/protocol.ts`; снимки формируются общим серверным адаптером поверх `lib/engine`. Все сообщения — JSON. Общие команды:

| Клиент → сервер | Назначение |
| --- | --- |
| `create { playerName, deckList, heroId? }` | Создать комнату и занять первое место. Код создаёт сервер через общий `createRoomCode`. |
| `join { roomCode, playerName, deckList, heroId?, resumeToken? }` | Занять второе место либо восстановить своё с секретом. |
| `intent { intent, revision? }` | Попытаться выполнить действие; клиент отправляет текущую ревизию снимка. |
| `sync` | Запросить актуальный снимок своего места. |
| `ping` | Проверить соединение. |
| `leave` | Явно покинуть комнату. |

`intent` содержит одно из действий: `playCard`, `attack`, `endTurn`, `heroPower`, `buyCard`, `mulligan`, `stake`, `unstake`, `concede`. Дополнительные действия сохраняют возможности общего движка. `buyCard` покупает случайную копию из исходного состава своей пустой колоды за 2 приказа: один раз за свой ход, при наличии места в руке. Клиент не задаёт цену или выбранную карту; исходный состав остаётся на сервере. Усталость сохраняется. Для обновления с 8 октября фронт и WS-сервис нужно развернуть вместе (99 карт, новые стартовые колоды и половинный ответный удар). `cardId` и элементы `cardIds` — **UID экземпляров**, не ID карты из каталога; `targetId` — UID бойца либо `hero` для казны противника. `deckList` содержит ID из каталога и проверяется сервером по существующим ограничениям колод.

Пример завершения хода:

```json
{"type":"intent","revision":12,"intent":{"type":"endTurn"}}
```

| Сервер → клиент | Назначение |
| --- | --- |
| `joined { you, roomCode, resumeToken, opponent }` | Подтвердить место `p1` / `p2` и выдать секрет восстановления. |
| `state { snapshot }` | Полный доступный этому игроку снимок после присоединения или принятого хода. |
| `error { reason, code, fatal? }` | Объяснить отклонённую команду. |
| `gameOver { winner, reason }` | Результат `p1` / `p2`; `draw` сохраняет возможность ничьей движка. |
| `opponentLeft` | Сообщить об отключении соперника. |
| `pong { serverTime }` | Подтвердить проверку соединения. |

Сервер владеет колодами, RNG, очередью хода, ресурсами, здоровьем и результатом. Снимок содержит свою руку, публичных бойцов и указы, размеры чужой руки/колод и доступные действия. Чужая рука, порядок колод и RNG не передаются.

Одного имени для реконнекта недостаточно: чужое имя видно противнику. Секрет `resumeToken` хранится в вкладке и не добавляется в приглашения, URL или публичные снимки. Вход по тому же имени и своему секрету возвращает прежнее место и полный актуальный снимок.

Серверный таймер передаёт ход через 75 секунд. Разыгрывание карты не продлевает срок текущего хода. Если не завершена стартовая замена, сервер сохраняет текущую руку перед передачей хода. Комнаты очищаются после 30 минут без действий игроков; keepalive-сообщения не продлевают жизнь комнаты.

Пока создатель ждёт второго игрока, случайный обрыв оставляет его комнату доступной для восстановления; кнопка закрытия комнаты удаляет её сразу. Если оба уже занявших места игрока отключились, комната удаляется сразу, в том числе при одновременном обрыве сети у обоих. Поэтому тест реконнекта на 10 секунд выполняется с одним отключённым клиентом и вторым остающимся за столом.

Клиент при потере связи остаётся в режиме просмотра, запрещает отправку ходов и переподключается с экспоненциальной паузой. Он синхронизирует состояние после реконнекта и не повторяет автоматически отправленные ранее действия.

## Остальные режимы

Этот WS-сервис обслуживает **свои бесплатные игры**. Тренировка против ИИ работает локально. Случайный подбор сохраняет существующий HTTP API; публикация этого отдельного WS-сервиса сама по себе не переносит очередь случайных игр на Render. Состояние и границы обоих транспортов описаны в `docs/multiplayer-readiness.md`.
